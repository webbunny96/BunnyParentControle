# Приклад конфігурації (config.json)

Опис полів конфігураційного файлу `config.json`.

## Структура конфігурації

```json
{
    "admin_id": 0,
    "otp": "ABCD1234",
    "schedule": { ... },
    "awaiting_time": null,
    "admin_ids": [],
    "force_block": false,
    "parent_password": null,
    "time_limit_minutes": 0,
    "start_time": 0
}
```

## Опис полів

### `admin_id` (застаріле)
- **Тип:** `number`
- **Опис:** ID адміністратора Telegram (застаріле поле, використовуйте `admin_ids`)
- **Приклад:** `123456789`
- **Примітка:** Це поле автоматично мігрується в `admin_ids` при завантаженні конфігурації

### `otp`
- **Тип:** `string`
- **Опис:** Код реєстрації для підключення адміністраторів через QR-код або Telegram бота
- **Приклад:** `"ABCD1234"`
- **Примітка:** Генерується автоматично при першому запуску, якщо не вказано

### `schedule`
- **Тип:** `object`
- **Опис:** Розклад блокування для кожного дня тижня
- **Структура:**
  ```json
  {
    "0": { "start": "22:00", "end": "07:00", "enabled": false },
    "1": { "start": "22:00", "end": "07:00", "enabled": false },
    ...
    "6": { "start": "22:00", "end": "07:00", "enabled": false }
  }
  ```
- **Дні тижня:**
  - `"0"` - Понеділок
  - `"1"` - Вівторок
  - `"2"` - Середа
  - `"3"` - Четвер
  - `"4"` - П'ятниця
  - `"5"` - Субота
  - `"6"` - Неділя

#### Поля розкладу для кожного дня:

- **`start`** (`string`): Час початку блокування у форматі `HH:MM` (наприклад, `"22:00"`)
- **`end`** (`string`): Час кінця блокування у форматі `HH:MM` (наприклад, `"07:00"`)
- **`enabled`** (`boolean`): Чи активний розклад для цього дня
  - `true` - розклад активний, комп'ютер буде заблоковано в зазначений час
  - `false` - розклад вимкнено

**Примітка:** Для нічних інтервалів (наприклад, `22:00` - `07:00`) система автоматично обробляє перехід через північ.

### `awaiting_time`
- **Тип:** `object | null`
- **Опис:** Тимчасове поле для очікування введення часу в Telegram боті
- **Структура:** `{"day": "0", "mode": "start"}` або `null`
- **Примітка:** Використовується внутрішньо системою, не потрібно встановлювати вручну

### `admin_ids`
- **Тип:** `array<number>`
- **Опис:** Список ID адміністраторів Telegram
- **Приклад:** `[123456789, 987654321]`
- **Примітка:** Підтримується кілька адміністраторів. ID додаються автоматично при реєстрації через QR-код або код

### `force_block`
- **Тип:** `boolean`
- **Опис:** Примусове блокування комп'ютера
- **Значення:**
  - `true` - комп'ютер заблоковано незалежно від інших умов
  - `false` - блокування визначається розкладом або лімітом часу
- **Примітка:** Найвищий пріоритет серед умов блокування

### `parent_password`
- **Тип:** `string | null`
- **Опис:** Батьківський пароль для доступу до налаштувань
- **Приклад:** `"mySecurePassword123"`
- **Примітка:** 
  - Мінімум 4 символи
  - Зберігається у відкритому вигляді (не зашифрований)
  - Потрібен для доступу до GUI налаштувань та закриття програми

### `time_limit_minutes`
- **Тип:** `number`
- **Опис:** Ліміт часу роботи комп'ютера в хвилинах
- **Значення:**
  - `0` - без ліміту
  - `15` - 15 хвилин
  - `30` - 30 хвилин
  - `60` - 1 година
  - `120` - 2 години
  - Інші значення - будь-яка кількість хвилин
- **Примітка:** Відлік починається з моменту встановлення ліміту

### `start_time`
- **Тип:** `number`
- **Опис:** Unix timestamp (секунди з 1 січня 1970) моменту початку відліку ліміту часу
- **Приклад:** `1705838400`
- **Примітка:** Встановлюється автоматично при встановленні `time_limit_minutes`, не потрібно встановлювати вручну

## Примітки

1. **Валідність JSON:** Файл має бути валідним JSON (без коментарів `//`)
2. **Автоматична нормалізація:** Система автоматично додає відсутні поля при завантаженні
3. **Міграція:** Старе поле `admin_id` автоматично мігрується в `admin_ids`
4. **Безпека:** Пароль зберігається у відкритому вигляді, використовуйте сильний пароль
5. **Резервне копіювання:** Рекомендується робити резервні копії `config.json` перед змінами

## Створення конфігурації

Якщо файл `config.json` не існує, система автоматично створить його з дефолтними значеннями при першому запуску.

Для ручного створення:
1. Скопіюйте `config.example.json` в `config.json`
2. Відредагуйте значення відповідно до ваших потреб
3. Переконайтеся що JSON валідний (перевірте через JSON валідатор)
